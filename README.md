# TON Vanity · Rust + OpenCL

`brut-wallet` создаёт **новый собственный TON W5-кошелёк** с выбранным окончанием
адреса. Поиск работает локально на CPU или GPU через OpenCL, сохраняет прогресс
и продолжается после перезапуска.

- OpenCL-конвейер из двух пачек с повторным использованием буферов.
- Независимая CPU-проверка каждой находки и самопроверка на публичных векторах.
- Постоянный размер checkpoint, атомарные записи и блокировка параллельного запуска.
- Остановка по Ctrl+C, восстановление после сбоя и завершение после первой найденной пачки.
- Один исполняемый файл; Python, Node.js и CUDA Toolkit для запуска не нужны.

Программа не подключается к сети. Проверка балансов и команда `watch` удалены.

## Быстрый старт

Нужны Rust 1.89+ и системный линкер. Для GPU дополнительно нужен драйвер с OpenCL;
CPU-проверка и CPU-поиск работают без него. Версии зависимостей закреплены в `Cargo.lock`.

```sh
cargo build --release --locked
```

Бинарник находится в `target/release/brut-wallet` (`brut-wallet.exe` на Windows).
При заданном `CARGO_TARGET_DIR` замените `target` на этот каталог.
Скопируйте бинарник и `config.example.toml` в отдельный приватный каталог с правом записи.
Дальнейшие команды выполняются из него.

Linux:

```sh
./brut-wallet check
cp config.example.toml config.toml
# Для первого CPU-запуска задайте target_suffix = "cafe" и batch_size = 128.
./brut-wallet search --cpu --batches 1
```

Одна пачка проверяет работу поиска и сохранения, но не гарантирует находку.
Уберите `--batches 1`, чтобы искать до совпадения или Ctrl+C.

Windows PowerShell, GPU:

```powershell
.\brut-wallet.exe check
.\brut-wallet.exe devices
Copy-Item config.example.toml config.toml
# Задайте короткий target_suffix и индекс GPU device_index в config.toml.
.\brut-wallet.exe check --gpu
.\brut-wallet.exe search
```

Суффикс содержит 4–10 символов Base64URL: `A–Z`, `a–z`, `0–9`, `_`, `-`.
Регистр учитывается. Начинайте с четырёх символов: длина резко увеличивает объём поиска.
Текущий суффикс по умолчанию — `myrsgraal`; для быстрого знакомства его нужно заменить.

## Команды и настройки

| Команда | Назначение |
|---|---|
| `check` | CPU-самопроверка на публичных векторах |
| `check --gpu` | Дополнительно сравнить GPU с CPU |
| `devices` | Показать устройства OpenCL |
| `benchmark --cpu` | Измерить CPU на публичных данных |
| `benchmark` | Измерить GPU-конвейер и времена этапов |
| `search --cpu` | Начать или продолжить CPU-поиск |
| `search` | Начать или продолжить GPU-поиск |

`--directory /путь/к/сессии` задаёт существующий каталог данных для любой команды.
Без него данные находятся **рядом с бинарником**, а не в текущем каталоге терминала.
`search --batches N` ограничивает число пачек одного запуска.

Без команды программа при первом запуске запрашивает суффикс и начинает GPU-поиск.
Существующая сессия продолжается автоматически. CPU выбирается явно через `--cpu`;
при недоступности OpenCL скрытого переключения на CPU нет.

В [config.example.toml](config.example.toml) задаются суффикс, индекс устройства,
размер пачки и глубина конвейера. `batch_size` — 128–131072, кратно 128;
`pipeline_depth` — 2. Для CPU используйте 128: большая пачка задерживает штатную остановку.
Размер конфига ограничен 128 KiB; неизвестные поля отклоняются.
Старая секция `[watch]` игнорируется с предупреждением и не мешает продолжить TON-сессию.

## Результат и восстановление

Формат кошелька: TON W5/V5R1, mainnet, workchain 0, non-bounceable адрес `UQ`,
wallet_id `0x7fffff11`. Ключ выводится из 24 английских слов BIP39 с пустым
passphrase по пути SLIP-0010 `m/44'/607'/0'`.

- `config.toml` — настройки поиска.
- `session.toml` — ключ последовательности, цель и подтверждённый индекс.
- `wallets.txt` — найденные адреса и 24 слова для каждого кошелька.
- `session.lock` — файл блокировки; удаление имени не освобождает OS lock.

**`session.toml` и `wallets.txt` содержат секреты и дают доступ к кошелькам.**
Шифрования новых файлов нет. Используйте приватный каталог; Unix-файлы создаются
с правами 0600, на Windows действуют ACL каталога. Не добавляйте сессии, слова
и старые `master-key.bin` в Git, скриншоты или отчёты об ошибках.

Находка записывается раньше checkpoint. Повтор после сбоя не дублирует результат.
После первой найденной пачки программа сохраняет уже отправленные пачки и завершается.
Повторный запуск завершённой сессии показывает адрес и путь к результатам без GPU.

Первый Ctrl+C останавливает отправку новых пачек и сохраняет подтверждённую работу.
Второй завершает процесс принудительно с кодом 130; неподтверждённая пачка повторится.
Во время подготовки GPU первый Ctrl+C сразу завершает процесс, не ожидая драйвера.
Зависание внутри ядра ОС или неисправного драйвера не позволяет гарантировать остановку.

Для переноса после штатной остановки сохраните `config.toml`, `session.toml` и
`wallets.txt`. Для другой цели создайте новый каталог: суффикс существующей сессии
нельзя молча изменить.

Версия 0.2 читается с прежним `master-key.bin`: перед миграцией сохраняется backup,
старые файлы не удаляются. Парольная оболочка v1 не поддерживается;
для неё нужен прежний бинарник.

При импорте выбирайте BIP39, пустой passphrase и указанный путь. TON-native mnemonic
может дать другой адрес. До использования проверьте совпадение адреса в выбранном
кошельке; совместимость конкретного приложения-получателя ещё требует проверки.

## Проверки и ограничения

```sh
cargo fmt --all --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --all --locked
```

CI выполняет эти проверки и release-сборку на Linux и Windows.
Тесты покрывают независимые TON SDK-векторы, поток ChaCha20, остановку, блокировку,
сбой записи, восстановление, миграцию и совместимость конфигов.
Тестовые мнемоники публичны и не подходят для хранения средств.

GPU-тест исключён из обычного прогона. На выбранном устройстве запускайте `check --gpu`.
Linux CPU проверяется локально; Windows-бинарник кросс-собирается на Linux.
Кросс-компиляция не подтверждает запуск на Windows, OpenCL или RTX 3060.
Измеренной производительности текущей GPU-версии пока нет.
