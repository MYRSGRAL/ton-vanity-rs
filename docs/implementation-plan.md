# Проверки перед публичным релизом

Цель релиза — воспроизводимо собираемый TON W5 vanity-генератор с понятным первым
запуском, сохранением прогресса и проверяемым результатом.

## Автоматические проверки

- `cargo fmt --all --check`.
- `cargo clippy --all-targets --locked -- -D warnings`.
- `cargo test --all --locked`: SDK-векторы, границы конфигурации, resume, блокировки,
  аварийная остановка, атомарные записи и legacy-миграция.
- `cargo build --release --locked` и CPU-команда `check` на публичных данных.
- Проверка графа runtime-зависимостей: без сетевого клиента и адаптеров балансов.
- GitHub Actions на Linux и Windows; успешный локальный прогон не заменяет результат CI.

## Проверки на целевой машине

- `devices`, корректный `device_index`, затем `check --gpu`.
- `benchmark` с записью модели GPU, ОС, версии драйвера и размера пачки.
- Реальный поиск, Ctrl+C, повторный запуск и завершение после находки.
- Совпадение адреса после импорта BIP39 в выбранный TON-кошелёк.
- Запуск Windows-бинарника и проверка доступа к каталогу через ACL.

GPU и Windows нужно проверять исполнением на целевой машине.
Кросс-сборка и host-тесты не заменяют эту проверку.

## Комплект публикации

В Git входят исходники, `Cargo.lock`, тесты, конфиг-пример, документация,
лицензии и CI. Пользовательские конфиги, сессии, ключи, мнемоники, рабочие
резервные копии и сборочные каталоги остаются локально.

Архив релиза собирается по явному списку: бинарник, `config.example.toml`, README,
лицензии и third-party notices. К архивам прилагаются SHA-256.
Нельзя архивировать весь рабочий каталог: рядом с бинарником могут быть секреты сессии.

Перед публикацией проверить секреты, лицензии заимствованных ядер и актуальные
уязвимости зависимостей. Ошибка сканера не считается успешной проверкой.

## Автоматические релизы

Push в `main` запускает форматирование, Clippy, Rust-тесты, тесты упаковки,
release-сборку и CPU-самопроверку на Linux и Windows. После успешного завершения
обеих платформ workflow публикует архивы и `SHA256SUMS` в GitHub Releases.
Тег берётся из `package.version` в `Cargo.toml`: `1.0.0` становится `v1.0.0`.

Для следующего выпуска увеличьте версию в `Cargo.toml`, обновите запись проекта
в `Cargo.lock` и отправьте изменения в `main`. Если релиз этой версии уже есть,
проверки и сборки выполняются, публикация пропускается. Существующие теги и
архивы не перезаписываются. Ручной запуск workflow доступен через Actions.

Архивы упаковывает `scripts/package_release.py`; Python нужен только при сборке.
Состав ограничен бинарником, публичной документацией, конфигом-примером и лицензиями.
Лицензии, отсутствующие в Cargo-пакетах, берутся по закреплённым ссылкам с проверкой SHA-256.
