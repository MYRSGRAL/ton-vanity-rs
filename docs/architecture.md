# Проектирование TON vanity-генератора на Rust

Проект создаёт собственные TON W5 vanity-кошельки локально на CPU или OpenCL.
Сетевые адаптеры и проверка балансов в состав программы не входят.

## Назначение и границы

Создание нового собственного W5/V5R1-кошелька с заданным окончанием адреса UQ.
24 английских слова BIP39, пустой дополнительный пароль BIP39,
путь SLIP-0010 `m/44'/607'/0'`, mainnet, workchain 0, wallet_id 0x7fffff11.
Сохранение seed-фраз случайных чужих кошельков по признаку наличия средств
и индекс кошельков с балансом в реализацию не входят.


## Пользовательский сценарий

Один исполняемый файл для своей платформы: Windows x64 и Linux x64.
Код переносим; macOS CPU-режим требует отдельной проверки и сборки.
На Windows/Linux GPU-режим требует установленного драйвера с OpenCL;
Python, Node.js и CUDA Toolkit на машине пользователя не требуются.
При отсутствии OpenCL программа объясняет причину; переход на CPU явный.

При первом запуске один раз запрашивается окончание и сохраняется config.toml;
поиск начинается автоматически. Существующая сессия продолжается без подтверждения.
Выбор GPU не запрашивается: device_index по умолчанию 0, другой индекс задаётся
явно в TOML. CPU используется только с `--cpu`. Паролей и парольных флагов нет.
Если в wallets.txt уже есть результат текущей сессии, программа показывает адрес
и путь к файлу, затем завершается без инициализации GPU.
Новую цель создают как отдельную сессию, старые находки не перезаписываются.
При несовпадении конфигурации и сохранённой сессии запуск останавливается
с объяснением; история старой цели не выдаётся за прогресс новой.

Допустимые окончания: 4–10 символов Base64URL, регистр учитывается.
По умолчанию предлагается myrsgraal. Полное искомое выражение показывается
перед запуском. Пустой ввод, неправильные символы и некорректные параметры
GPU отклоняются до начала вычислений.

## TOML и файлы рядом с программой

config.toml содержит только публичные настройки:

```toml
schema_version = 1
target_suffix = "myrsgraal"
device_index = 0
batch_size = 65536
pipeline_depth = 2
```

Состояние и результаты находятся рядом с исполняемым файлом; отсутствие
прав записи приводит к понятной ошибке, без автоматического переноса данных.
Параллельные экземпляры защищены файловой блокировкой через стандартную
библиотеку Rust. Наличие имени lock-файла само по себе блокировкой не считается.

session.toml — открытый TOML с ключом потока, индексом следующего кандидата,
идентификатором сессии, целью и параметрами восстановления. Необязательное поле
found_index обозначает найденный результат; отсутствие поля совместимо со старыми
сессиями. Ключ потока позволяет восстановить кандидатов и хранится открытым.
Загрузка проверяет версию, длины и предел размера до выделения памяти.
Новые данные не шифруются, master-key.bin не создаётся.
Открытые session.toml и wallets.txt дают доступ к кошелькам.

При находке единый wallets.txt сразу получает читаемый блок: адрес и 24 слова
BIP39, а также идентификатор сессии и индекс для идемпотентности. Находка всегда
проверяется CPU, обновление файла атомарно и предшествует checkpoint. Отдельные
файлы находок и дополнительный экспорт для получения слов не нужны.
В консоли отображаются адрес и путь к wallets.txt, без слов и приватного ключа.
Ошибки и диагностика не содержат слов или ключей.

Совместимость с версией 0.2: имеющийся master-key.bin используется только для чтения
старой XChaCha20-Poly1305 оболочки версии 2. Перед первым открытым сохранением
создаётся резервная копия старого session.toml. Старые wallet-*.toml переносятся
идемпотентно в wallets.txt; оригиналы и master-key сохраняются. Отсутствующий,
неверный или повреждённый старый ключ вызывает отказ без порчи исходных данных.
Парольная оболочка версии 1 отклоняется без изменения файлов; для восстановления
таких данных используется прежний бинарник.
Резервная копия новых данных включает config.toml, session.toml и wallets.txt
после штатной остановки; для старых файлов сохраняются и их исходные ключи.

## Возобновление без огромной базы попыток

Используется ChaCha20Rng с 256-битным ключом из системного CSPRNG.
На кандидата расходуется 32 байта; номер кандидата определяет позицию потока.
Алгоритм, версия и формат позиционирования фиксируются в состоянии и тест-векторах.
Обновление зависимости не должно молча менять последовательность кандидатов.
Проверяется предел позиции, исключающий циклический переход генератора.
Разные индексы обозначают разные попытки; абсолютное отсутствие случайных
криптографических коллизий адресов не обещается.

Хранится сплошной завершённый диапазон индексов [0, next_index), а не список
миллиардов адресов. Память и размер checkpoint не растут с числом попыток.
Две GPU-пачки могут выполняться конвейером, но checkpoint продвигается только
по непрерывной последовательности полностью проверенных пачек.

Ctrl+C перестаёт подавать новые пачки, дожидается ограниченного числа уже
отправленных пачек, сохраняет находки и checkpoint, затем завершает процесс.
Admission пачки и отмена линеаризованы атомарно: отмена запрещает новые admission,
ранее принятые пачки завершаются. При подготовке OpenCL/публичной самопроверке
первый Ctrl+C завершает процесс без ожидания драйвера: поисковых пачек ещё нет.
Повторный Ctrl+C при поиске вызывает Unix `_exit(130)` либо Windows
`TerminateProcess` прямо из обработчика, обходя интерфейс, C `atexit` и DLL detach.
Файл состояния записывается через временный файл в том же каталоге, sync и
атомарную замену. Ошибка записи прекращает дальнейшее продвижение поиска.

После аварийного завершения может повториться незакоммиченная пачка.
Требование одновременно не повторить ни одной попытки и не потерять
незавершённую попытку при отключении питания не обещается.
Результат сохраняется раньше checkpoint; сессия и индекс определяют запись
в wallets.txt, повторное восстановление не создаёт дубликат. После первой найденной
пачки прекращается отправка новых; уже отправленные две GPU-пачки дренируются,
их результаты сохраняются, затем поиск завершается.

## Вычисления и производительность

Перенос существующего OpenCL-конвейера, сохранение всех 2048 итераций BIP39.
Тяжёлые операции остаются на GPU: BIP39, PBKDF2, SLIP-0010, Ed25519, StateInit,
CRC16 и полная 64-битная маска окончания. Rust управляет буферами и очередями.
Буферы переиспользуются; две пачки, ограниченная очередь и явные зависимости
OpenCL events сохраняют корректное владение входом и результатом каждой пачки.

Сначала сравнение корректности и скорости с исходной программой.
Прирост скорости от смены языка не заявляется заранее.
Профилируются H2D, KDF, SLIP-0010, Ed25519, фильтр, D2H и синхронизация.
Оптимизации принимаются только после одинаковых контрольных тестов и замера
на RTX 3060. GPU ноутбука пользователя без отдельной просьбы не запускается.
Без изменения криптографии допускаются пакетное заполнение энтропии,
переиспользование RNG и пропуск чтения hit-буфера при нуле совпадений.
Benchmark измеряет конвейер глубины 2 на нескольких пачках и профиль стадий;
CPU-бенчмарк остаётся на публичных данных. Выигрыш заранее не обещается.

## Живая консоль

Отдельные стадии: подготовка OpenCL/компиляция, публичная самопроверка, поиск,
остановка. При нулевой скорости прогноз — «нет данных до первой подтверждённой
пачки», а не бесконечность. После отмены поздние события не возвращают статус «Поиск».

Обновление примерно раз в секунду, независимо от продолжительности GPU-пачки.
Устройство, цель, скорость за последние пять секунд и средняя без инициализации,
обработанные попытки, uptime, сохранённый индекс, время последнего checkpoint,
число находок и состояние. Числа и длительности форматируются для чтения человеком.
Статистическое ожидание не обещает срок находки; вероятность «100%» не выводится
в каждой строке. В TTY используется одна обновляемая строка, в non-TTY — обычные
строки без ANSI. Диагностика через tracing, интерфейс — через stdout/stderr.

## Модули и этапы

1. config/pattern: TOML и валидация; crypto: независимый CPU эталон W5/BIP39.
2. session/storage: криптографический поток, открытое состояние, блокировка,
   атомарное сохранение wallets.txt и совместимость со старым форматом.
3. gpu: OpenCL-диспетчер, persistent buffers, CPU/GPU differential self-test.
4. app/ui: ввод цели, жизненный цикл сессии, Ctrl+C и живая консоль.
5. Проверки, review, Linux-сборка и Windows-сборка при наличии cross-toolchain.

## Зависимости

`opencl3` загружает OpenCL динамически. `bip39`, `hmac`, `sha2` и `ed25519-dalek`
реализуют CPU-эталон; `rand`/`rand_chacha` — системную энтропию и поток кандидатов.
`zeroize` очищает основные секретные буферы; `chacha20poly1305` нужен только для
чтения старых данных версии 0.2. `serde`, `toml` и `base64` обслуживают локальные форматы;
`tempfile` — атомарные записи; `clap`/`ctrlc` и `tracing` — CLI и диагностику.
`serde_json` используется только в тестах публичных SDK-векторов.
Версии закреплены в `Cargo.lock`.

HTTP-клиента, async runtime и адаптеров других сетей нет. Загрузка старого конфига
удаляет устаревшую секцию `[watch]` только из разобранного представления в памяти,
выводит предупреждение и строго валидирует остальные поля. Файл не перезаписывается.

## Критерии проверки

- Публичные тест-векторы BIP39 и SLIP-0010, адреса из TON SDK.
- Фильтр: положительные и отрицательные случаи, длины 4, 9, 10, регистр.
- Последовательность целиком совпадает с последовательностью после resume.
- Повреждённый checkpoint, смена цели, занятая блокировка и ошибка записи не
  теряют подтверждённые результаты; wallets.txt сохраняется раньше checkpoint.
- Новая сессия не создаёт master-key, данные открыты; права Unix 0600 либо
  наследуемые Windows ACL. Повтор сохранения не дублирует блоки wallets.txt.
- Миграция 0.2 создаёт backup сессии и переносит находки идемпотентно, сохраняя
  исходные файлы и ключ. Неверный ключ и парольная версия 1 дают отказ без порчи.
- CLI спрашивает только суффикс один раз; resume автоматический, GPU по TOML,
  CPU только по --cpu. Существующий результат текущей сессии завершает запуск без GPU.
- Первая найденная пачка прекращает новые отправки, pending-пачки сохраняются.
- 24 слова из wallets.txt восстанавливают тот же адрес; дополнительный экспорт не нужен.
- Скорость за пять секунд, средняя без инициализации, TTY/non-TTY формат и pipeline-2
  benchmark проверяются независимо от запуска реального GPU.
- cargo fmt --check, cargo clippy --all-targets -- -D warnings, cargo test.
- Старые настройки не мешают TON-поиску; неверные поля генератора отклоняются.
- Release smoke-test на CPU только на публичных фикстурах; GPU на RTX 3060
  проверяет пользователь. Результат кросс-компиляции не приравнивается к запуску.
- Для Cargo используется внешний transient build-каталог с flock корня.
  Нужные результаты и evidence сохраняются вне него; после сборок cargo clean.
