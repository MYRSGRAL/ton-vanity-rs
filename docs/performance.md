# Производительность OpenCL-конвейера

Измерений текущей TON-only сборки на целевом GPU пока нет.
Скорость и ускорение не заявляются до воспроизводимой проверки.

## Реализованные host-изменения

- Энтропия копируется одним `copy_from_slice` вместо цикла по кандидатам.
- Поток ChaCha20 заполняет всю пачку одним `fill_bytes`; 60 комбинаций seed,
  позиции и длины сверены с прежним расходованием по 32 байта. Порядок resume сохранён.
- При отсутствии совпадений GPU не выполняет чтение hit-буфера.
- Две CPU-пачки энтропии переиспользуются вместо новых аллокаций на каждом проходе.
- `benchmark` измеряет 16 пачек с двумя in-flight заданиями и FIFO collect/refill,
  а не сериализованный scan. Выводит CPU-подготовку и суммарные времена этапов GPU.

PBKDF2 сохраняет все 2048 итераций. CPU проверяет контрольный seed каждой GPU-пачки
и адрес каждой находки. Криптография не заменена и проверки не выключены.

## Что измерять на RTX 3060

На целевой машине запустить `check --gpu`, затем несколько одинаковых `benchmark`.
Профиль разделяет загрузку, сборку BIP39, PBKDF2, SLIP10, Ed25519, фильтр и чтение.
Сумма event-времён не равна общему времени: передачи могут перекрываться с compute.
Benchmark не сохраняет кошельки и не делает сетевых запросов.

Дальнейшие кандидаты для отдельного A/B-замера: local work size 64/128/256
(в исходном эталоне PBKDF2 default 128, сейчас драйвер выбирает размер), заранее
поставленный неблокирующий D2H, pinned host buffers, интервалы queued→start между
пачками и настройка размера loop-dispatch PBKDF2. Эти изменения без измерения
на RTX не принимались: они зависят от occupancy, драйвера и владения буферами.

Ускорение GPU от новых host-правок не заявляется без такого измерения.
